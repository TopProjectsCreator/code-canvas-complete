Exactly. The redesign I showed is solving the organization problem by creating a horizontal toolbar, but that creates a width problem. Your panel is narrow, so the UI should become more hierarchical, not wider. The key change I'd make is: Don't make “Built-in / Offline / BYOK” a permanent row of buttons. Make them part of the model picker. You really have three different concepts, and they shouldn't all compete for horizontal space: Mode → Chat / Build Model source → Built-in / Offline / BYOK Specific model → Flash / Pro / Gemma / Sonar Pro / etc. What I'd do Keep Chat / Build as the only prominent toggle: ┌───────────────────────────────┐ │  💬 Chat        </> Build     │ └───────────────────────────────┘ Then have one compact model button: ┌─────────────────────────────────┐ │ ✨  Sonar Pro          ˅         │ │     Built-in                    │ └─────────────────────────────────┘ When clicked, that opens the model picker: ┌─────────────────────────────────┐ │ Search models...                │ ├─────────────────────────────────┤ │  BUILT-IN                       │ │  ✨ Pro                         │ │  🔥 Flash                      │ │  ⚡ Lite                        │ │                                 │ │  OFFLINE                        │ │  ◉ gemma-4-E2B-it-ONNX          │ │                                 │ │  BYOK                            │ │  🔑 OpenRouter                  │ │  🔑 Pollinations.AI             │ └─────────────────────────────────┘ And if they select BYOK, then the provider/model choices appear: ┌─────────────────────────────────┐ │ 🔑 OpenRouter              ˅    │ │    Sonar Pro                    │ └─────────────────────────────────┘ That means your bottom bar stays narrow. So the actual bottom could be ┌──────────────────────────────────────────┐ │  💬 Chat     </> Build                   │ │                                          │ │  ✨ Sonar Pro · Built-in             ˅   │ │                                          │ │  📎  Ask me anything...             ➤   │ └──────────────────────────────────────────┘ That's much cleaner than: Lite | Flash | Pro | Offline | Chat Only | gemma-4... | Pollinations | OpenRouter Filter models | Search | Model... because your current design is effectively exposing the entire configuration system all the time. I'd also change "Offline" I wouldn't have a big green Offline button sitting beside the model tiers. “Offline” is actually a model source, not connection status. You currently have two meanings getting mixed together: Offline model = model runs locally Offline status = internet/API connection unavailable Those should be completely different things. For example: Model picker: ✨ Sonar Pro · Built-in or ◉ Gemma 4 E2B · Offline or 🔑 Sonar Pro · OpenRouter And separately, if you actually need connection status: ● Online could be a tiny status indicator near settings rather than a huge pill. And I would remove the "Chat Only" pill If you're going to have: Chat | Build then having: Chat Only somewhere else is redundant. Make the mode selector visually obvious: ┌───────────────┬───────────────┐ │  💬 Chat      │  </> Build    │ └───────────────┴───────────────┘ Selected mode gets the accent color. The overall hierarchy I'd use Row 1 — Mode [ 💬 Chat ] [ </> Build ] Row 2 — Model [ ✨ Sonar Pro · Built-in ˅ ] Row 3 — Input [ 📎 ] [ Ask me anything... ] [ ➤ ] That's it. Everything else—Built-in vs Offline vs BYOK, provider selection, model search, API keys, model list—goes inside the model picker. This would let you keep essentially the same narrow width as your current UI while making the architecture much easier to understand.
